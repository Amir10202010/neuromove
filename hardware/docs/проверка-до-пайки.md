# Проверка до пайки: плата, один датчик, приложение

Зачем: прежде чем паять кабели к трём датчикам, убедиться, что вся цепочка работает — плата,
кабель, драйвер, прошивка, датчик и приложение. Если что-то сломано, это видно сразу, а не после
вечера пайки. Три части, по порядку; каждая заканчивается проверкой «что должно быть».

Компьютер — мак Амирхана: на нём уже лежат прошивка и приложение. На Windows всё так же,
отличия написаны рядом. Схема подключения — [`../diagrams/схема-подключения.png`](../diagrams/схема-подключения.png),
полная инструкция по стенду — [`firmware/README.md`](../../firmware/README.md).

| Часть | Что нужно | Время |
|---|---|---|
| 1. Плата без датчиков | плата, кабель USB-A → USB-C с передачей данных, ноутбук | 30–40 минут в первый раз: установка Arduino IDE |
| 2. Один датчик | запасной, четвёртый GY-521; угловая гребёнка из его комплекта; 5 проводов мама-мама; паяльник | 10 минут пайки + 15 минут проверки |
| 3. Приложение | Chrome или Edge | 10 минут |

## Часть 1. Плата без датчиков

### 1.1. Arduino IDE и пакет плат ESP32 — один раз

1. Скачать Arduino IDE 2 с https://www.arduino.cc/en/software и установить.
2. Открыть настройки: на маке меню **Arduino IDE → Settings** («Настройки»), на Windows **File → Preferences**.
   В поле **Additional boards manager URLs** («Дополнительные ссылки для Менеджера плат») вставить:
   ```
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```
   Это ссылка из официальной инструкции Espressif:
   https://docs.espressif.com/projects/arduino-esp32/en/latest/installing.html
3. Слева — значок **Boards Manager** («Менеджер плат»). В поиске набрать `esp32`, у пакета
   **esp32 by Espressif Systems** нажать «Установить». Качается несколько сотен мегабайт, 5–10 минут.
   Прошивка проверена на версиях 2.0.17 и 3.3.12: если новая версия не соберёт её, выбрать 3.3.12
   в том же окне.

### 1.2. Открыть прошивку

**File → Open** («Файл → Открыть») → `firmware/NeuroMoveStand/NeuroMoveStand.ino`.
Остальные файлы папки откроются вкладками: `config.h`, `mpu6050.h` и другие. Ничего не менять.

### 1.3. Подключить плату и выбрать её

1. Плату — кабелем USB-A → USB-C к ноутбуку. На плате загорится красный светодиод **PWR**.
   Не горит — другой кабель или другой порт ноутбука. Кабель USB-C ↔ USB-C плату может не запитать.
2. **Tools → Board → esp32 → ESP32 Dev Module** («Инструменты → Плата»).
3. **Tools → Port** («Порт»): на маке — `/dev/cu.usbserial-…`, на Windows — `COM…` с подписью CH340.
   Порта нет — смотрите таблицу «Если что-то не так» внизу.
4. **Tools → Upload Speed: 460800**. На маке лучше сразу так: встроенный драйвер CH340 на 921600
   ненадёжен. На Windows можно оставить 921600.
5. **Tools → Core Debug Level: None** — так стоит по умолчанию, просто проверить.

### 1.4. Загрузить прошивку

Кнопка **Upload** («Загрузить») — стрелка вправо слева вверху. Первая сборка идёт 1–3 минуты.
Внизу в окне вывода по порядку:

```
Connecting....
Chip is ESP32-…
Writing at 0x… (100 %)
Hard resetting via RTS pin...
```

Не подключается (`Failed to connect to ESP32`, `Timed out waiting for packet header`) — нажать
«Загрузить» ещё раз и, когда появится `Connecting....`, зажать на плате кнопку **BOOT** на 2–3 секунды.

### 1.5. Монитор порта

1. **Tools → Serial Monitor** («Монитор порта») или значок лупы справа вверху.
2. В панели монитора, справа от поля ввода, выбрать **New Line** («Новая строка») и **460800 baud**.
   Не 921600: 12 октября на маке с этой платой на 921600 шли одни каракули, поэтому прошивка
   говорит на 460800.
3. Нажать на плате кнопку **EN** — это сброс.

**Что должно быть:**

```
# NeuroMove NM-01, прошивка 0.1: датчиков найдено 0 из 3. help — команды
# нет ни одного датчика: проверьте питание 3V3, GND, SDA, SCL и вывод AD0. Ищу снова каждые 2 с
```

Вторая строка повторяется каждые 2 секунды — без датчиков так и должно быть. Перед первой строкой
может мелькнуть строчка непонятных знаков: это загрузчик самой платы, он говорит на другой скорости.
Непонятные знаки идут всё время — скорость монитора не 460800.

4. В поле ввода монитора набрать `scan` и нажать Enter. Ответ:

```
# шина 0 (SDA 21, SCL 22): никого — проверьте провода и питание
# шина 1 (SDA 32, SCL 33): никого — проверьте провода и питание
# 0x68 — датчик с AD0 на GND, 0x69 — с AD0 на 3V3
```

**Итог части 1:** плата, кабель, драйвер и прошивка работают. Это шаг 0 из [`firmware/README.md`](../../firmware/README.md), раздел 4.

## Часть 2. Один датчик

### 2.1. Пайка: запасной модуль, угловая гребёнка

Гребёнку паяем **только запасному, четвёртому модулю**. Три рабочих модуля пойдут в корпус,
а с гребёнкой модуль в него не влезет — им кабель паяется прямо в отверстия.

1. В комплекте модуля две гребёнки: прямая и угловая (штыри загнуты под прямым углом). Берём угловую:
   модуль будет лежать на столе ровно, провода наденутся сбоку.
2. Короткие концы гребёнки вставить в 8 отверстий **со стороны чипа**, длинные концы смотрят
   в сторону от платы. Перевернуть, припаять 8 точек с обратной стороны.
3. Посмотреть на пайку: каждая точка — блестящий конус, соседние точки не слиплись.
4. Подписать модуль маркером: «ТЕСТ».

Понадобится запасной вместо сломанного рабочего — гребёнку откусить у самой платы,
кабель паять к остаткам штырей.

### 2.2. Провода — USB отключён

Пять проводов мама-мама. Выводы на плате ищите по надписям рядом с ними.

| Вывод датчика | Вывод платы | Где на плате (разъём USB внизу, чип сверху) |
|---|---|---|
| VCC | **3V3** | правый ряд, самый нижний |
| GND | **GND** | правый ряд, второй снизу |
| SCL | **D22** | правый ряд, второй сверху |
| SDA | **D21** | правый ряд, пятый сверху |
| AD0 | **GND** | левый ряд, второй снизу, рядом с VIN |
| XDA, XCL, INT | — | не подключать |

- **VCC — только на 3V3**, не на VIN: на VIN 5 вольт.
- Перед включением ещё раз проверить VCC и GND: перепутать их — можно сжечь модуль.
- AD0 на GND даёт адрес 0x68. Для прошивки это место «плечо», правая рука: `upper_r`.

### 2.3. Включить и проверить

1. Датчик положить на стол ровно, чипом вверх. Подключить USB, открыть монитор порта (460800),
   нажать **EN**.

   **Что должно быть:** первая строка `датчиков найдено 1 из 3`, затем паспорт:

   ```
   # imu-csv v1
   # device=NM-01 fw=0.1 rate_hz=100 acc_g=4 gyro_dps=1000 sensors=upper_r
   # board=esp32 i2c_hz=100000 arm=right
   # id_upper_r=…
   seq,upper_r_ax,upper_r_ay,upper_r_az,upper_r_gx,upper_r_gy,upper_r_gz
   ```

   И дальше — строки чисел, 100 в секунду. Это поток данных, так и должно быть. Числа в строке:
   номер отсчёта, ускорение X, Y, Z, поворот X, Y, Z. У датчика, лежащего чипом вверх, третье число
   после номера — около **8192**: это 1 g по оси Z.

   Строка `# внимание: upper_r отвечает WHO_AM_I 0x72…` — копия чипа MPU-6050. Работать с ней можно;
   записать, какое число.

2. Строки бегут быстро. Чтобы прочитать ответ на команду, выключите автопрокрутку — кнопка
   **Toggle Autoscroll** («Автопрокрутка») в правом верхнем углу панели монитора.
3. `scan` — должно быть:

   ```
   # шина 0 (SDA 21, SCL 22): 0x68
   # шина 1 (SDA 32, SCL 33): никого — проверьте провода и питание
   ```

   Шина 1 пустая — правильно: датчик груди не подключён.

4. `info` — у датчика:

   ```
   # upper_r: ускорение 0.01 -0.02 1.00 g, длина 1.00 g; поворот 0.4 -1.1 0.2 °/с
   ```

   Числа будут свои. **Датчик в порядке**, если длина от 0,89 до 1,11 g, а каждое из трёх чисел
   поворота — не дальше 20 °/с от нуля. Строки `trunk: нет на шине 1` и `fore_r: нет на шине 0` —
   правильно: этих датчиков нет.

5. Наклонить датчик — в потоке меняются первые три числа после номера. Резко повернуть — прыгают
   последние три.
6. **Закрыть монитор порта** — крестик на его вкладке. Пока он открыт, приложение порт не получит.

Записать в файл: текст ответа `info`, строку `# id_…` и есть ли строка про WHO_AM_I — это шаг 1
приёмки ([`../../website/docs/ENGINEERING_10H/HARDWARE_ACCEPTANCE.md`](../../website/docs/ENGINEERING_10H/HARDWARE_ACCEPTANCE.md)).

## Часть 3. Приложение

1. Из корня репозитория откройте Терминал:

   ```bash
   cd website
   npm run dev
   ```

   Должна появиться строка `Local: http://localhost:5173/`. Терминал не закрывать, пока идёт проверка.
   На другом компьютере сначала `npm install` в той же папке.
2. Открыть в **Chrome** или **Edge**: http://localhost:5173/#/devices — сразу страница «Датчики».
   Safari и Firefox не умеют подключать устройства по USB.
3. В «Источниках данных» — карточка **USB (Web Serial)** → **«Подключить»**. Chrome откроет окно
   выбора порта: на маке — устройство с `cu.usbserial` в названии, на Windows — `USB-SERIAL CH340 (COM…)`.
   Выбрать → «Подключиться».
4. **Что должно быть** в карточке «Текущее подключение»:
   - значок **«Поток данных активен»**;
   - формат — `imu-csv v1`, частота — **100 Hz · около 100/s**, диапазоны — ±4 g · ±1000 °/s;
   - в таблице датчиков — **«Правое плечо»** с зелёной точкой, связь около 100%.
5. **Проверка сигнала.** Угол считается от того положения, в котором датчик лежал при подключении.
   Лежит ровно — около 0°. Поставить на ребро — около 90°. Вернуть — снова около 0°.
   Вращение по столу, не отрывая, угол не меняет: это поворот, а не наклон.
6. «Отключить». В Терминале — Ctrl+C.

**Итог:** датчик, плата, прошивка, драйвер и приложение работают вместе. Можно паять кабели к трём
рабочим модулям — по [`../diagrams/схема-подключения.png`](../diagrams/схема-подключения.png) и [`firmware/README.md`](../../firmware/README.md), раздел 2.

## Если что-то не так

| Что видно | Почему | Что делать |
|---|---|---|
| Светодиод PWR не горит | кабель или порт ноутбука; кабель USB-C ↔ USB-C | другой кабель, USB-A → USB-C |
| В «Инструменты → Порт» нет платы | кабель только для зарядки; на Windows нет драйвера | другой кабель — у зарядного внутри 2 жилы вместо 4. На Windows — драйвер CH340: обычно ставит Windows Update, иначе с сайта производителя WCH, файл CH341SER. На маке драйвер встроен; старые драйверы WCH ему мешают |
| `Failed to connect to ESP32` | плата не вошла в режим загрузки | зажать BOOT, когда появится `Connecting....`; Upload Speed 460800 или 115200 |
| Ошибка при сборке | новая версия пакета esp32 | в «Менеджере плат» поставить esp32 3.3.12 |
| В мониторе непонятные знаки | скорость монитора не та | 460800. Прошивка, собранная до 12 октября, говорит на 921600 — перепрошить |
| `нет ни одного датчика`, хотя датчик подключён | провод, пайка гребёнки или перепутаны VCC/GND | проверить провода по таблице 2.2; пайку — на просвет; мультиметром между VCC и GND модуля 3,2–3,4 В |
| `scan` показывает 0x69, а не 0x68 | AD0 не на GND | провод AD0 — на GND |
| SDA и SCL перепутаны | датчика «нет» | D21 — SDA, D22 — SCL |
| Длина далеко от 1 g | модуль или пайка | записать числа; это запасной — для стенда возьмём рабочий |
| Приложение: «Устройство не прислало паспорт» | монитор порта открыт или выбран не тот порт | закрыть монитор, подключить заново |
| Карточка USB серая, «Не поддерживается» | не Chrome и не Edge | открыть в Chrome |
| В мониторе строки `[E][Wire.cpp…]` | в Arduino IDE включены логи ядра | Tools → Core Debug Level: None, загрузить снова |
