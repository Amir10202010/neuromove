# Сайт NeuroMove — веб-приложение

Объективная оценка движений в детской реабилитации: носимые IMU-датчики → углы в суставах,
симметрия, плавность, компенсация туловищем → отчёт и динамика по курсу терапии.

Замысел проекта и цели к Demo Day — [`../README.md`](../README.md); контракт с железом,
формулы и план софта — [`../софт.md`](../софт.md).

> ⚠️ **Прототип.** Инструмент для мониторинга реабилитации и исследований. Не является
> медицинским изделием, не ставит диагноз и не заменяет клиническую оценку и шкалы
> (GMFCS, GMFM, модифицированная шкала Эшворта). Всё демо-пространство — вымышленные
> пациенты и симулированное устройство, подписано «ДЕМО».

## Как открыть

**Без установки — для показа в клинике.** Файл [`demo/NeuroMove.html`](demo/NeuroMove.html)
открывается двойным щелчком в Chrome или Edge: всё внутри (код, стили, шрифты), интернет не нужен,
данные хранятся в браузере этого компьютера. Проверено: по `file://` страница открывается,
данные пишутся в IndexedDB, ошибок в консоли нет.

**Для разработки** (нужен Node.js 20+):

```bash
cd website
npm install
npm run dev          # http://localhost:5173
```

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер разработки с горячей перезагрузкой |
| `npm run build` | сайт в `dist/` — для любого хостинга (GitHub Pages и т. п.) |
| `npm run build:demo` | один файл `demo/NeuroMove.html` — для показа без интернета |
| `npm test` | юнит-тесты (Vitest): алгоритмы, движок, контракт, архив, выгрузка |
| `npm run e2e` | сквозные тесты Playwright в установленном Chrome — компьютер и телефон |
| `npm run docs:check` | рендер каждой диаграммы Mermaid из `docs/` |
| `npm run typecheck` | проверка типов TypeScript (strict) |
| `npm run lint` | ESLint с правилами хуков React |

**Переменные окружения** не нужны: приложение целиком работает в браузере, сервера нет.
В обеих сборках — политика безопасности (CSP): браузер запрещает странице любые сетевые запросы
(`connect-src 'none'`). Обещание «данные остаются на компьютере» закреплено технически и проверено
сквозным тестом.
Адреса внутри — с решёткой (`#/patients/…`), поэтому сайт открывается и из подпапки
GitHub Pages, и с диска.

### Публикация на Vercel

Корень проекта в Vercel — `website`, фреймворк — Vite. Файл `vercel.json`
задаёт сборку `npm run build` и папку результата `dist`. Переменные окружения
и перенаправления для маршрутов не нужны.

Для публикации из терминала после входа в аккаунт Vercel:

```bash
cd website
npx vercel login
npx vercel --prod
```

Офлайн-демо и документация исключены из загрузки через `.vercelignore`.
Локальная привязка к аккаунту и проекту (`.vercel/`) не хранится в Git.

⚠️ Web Serial и Web Bluetooth (настоящие датчики) есть только в Chrome и Edge на компьютере,
в защищённом контексте: `https://`, `localhost`. Страница с диска Chrome тоже считает защищённой —
`navigator.serial` там есть (проверено 1 октября), но с настоящим портом не проверено.
Симулятор работает везде.

## Демо за 3 минуты

На стартовой странице есть **«Попробовать демо»** (на первом экране, в финале, в подвале и «Демо»
в верхней панели). Одна кнопка: демо сбрасывается в исходное состояние, открывается карточка
первого ребёнка (Алихан) и **вступление**: одна фраза о том, что измеряет NeuroMove, три кадра пути
с подписью в одно слово (пациент, тест, итог) и одна кнопка «Начать» (или «Осмотреться без гида»).
Дальше **гид из 8 шагов в виде подсказки у элемента**: всё, кроме нужного блока, приглушено, рядом
заголовок и не больше одной короткой фразы. Если нужно что-то нажать, заголовок говорит, что сделать
(«Начните тест»), а настоящая кнопка приложения обведена; своей кнопки у гида нет. Если шаг только
объясняет, в подсказке «Далее». Ушёл с шага на другой экран: гид говорит «Вы ушли с шага…»
и возвращает кнопкой. В конце **«Вы прошли весь путь»** и «Пройти ещё раз». Тест вживую идёт около
минуты. Гид, вступление и итог переживают перезагрузку: они в sessionStorage вкладки. Полный
сценарий: [`docs/DEMO.md`](docs/DEMO.md).

**Что это демо, говорит только тёмная полоса сверху** («Демо», одна строка про симуляцию, «Гид»,
«Сбросить демо»). На экранах нет пометок «Демо-данные» и «Симулятор», гид и вступление не повторяют
«это симуляция», в текстах интерфейса нет длинного тире (решение 15 октября 2026). Дети в демо
названы вымышленными именами (Алихан, Айша, Нурислам, Томирис, Данияр, Амина), а не кодами P01–P06
(решение 17 октября 2026); коды остались внутренним ключом, от которого зависят числа. Исключение одно: лист печати и отчёт для семьи на бумаге несут водяной знак
«ДЕМО · СИМУЛИРОВАННЫЕ ДАННЫЕ», потому что лист уходит из приложения без полосы. На экране знака нет.

Кто открыл приложение сам, без гида, видит на главной строку **«Впервые здесь? Гид покажет весь
путь»** и кнопку «Начать гид». Крестик прячет её насовсем.

**Простой вид по умолчанию** (17 октября 2026): на экране только то, что нужно сейчас. Диагноз,
протокол, длительность, «Запись полная», «Шаг завершён», подписи «поражённая» и сноски не
повторяются на каждом экране; второстепенное лежит за «Показать подробности» (один переключатель
на всё приложение): цифры дня на главной, форма ДЦП и GMFCS/MACS в списке пациентов, протокол
и полнота записи в списке сеансов, описания протоколов и датчики на экране «Новый тест»,
выгрузка CSV и оговорка в аналитике. Таблица «Как идут дела» с главной убрана: она есть
в «Аналитике».

| # | Шаг | Что показать |
|---|---|---|
| 1 | Пациент | Карточка Алихана в простом виде: одна фраза («на 13° выше, чем в начале курса») и три картинки с цифрами — подъём руки (серый сектор — начало курса, оранжевый — прибавка, ромб — цель врача), правая и левая рядом, помощь корпусом |
| 2 | Сегодняшний тест | Быстрая проверка: подъём вперёд и локоть, сначала менее поражённая сторона. У каждого шага плана — значок движения |
| 3 | Датчики | Пять датчиков выходят на связь — на схеме тела. Заряд, связь и проверка сигнала — «Показать подробности» |
| 4 | Тест вживую | Одна карточка: что делать, повторы, крупный угломер с прошлым сеансом и целью, фигурка-силуэт с датчиками на руке. Живые кривые, повторы, сигнал — «Показать подробности». Кнопка «Обрыв связи на 5 с» в карточке гида — сеанс встаёт на паузу и продолжается без потерь |
| 5 | Итог | Одна фраза и строка на движение: схема обеих рук по настоящим углам, градусы, изменение к прошлому сеансу. Таблица, плавность, графики и черновик заключения — «Показать подробности» |
| 6 | Динамика | Сегодняшний сеанс уже в карточке: цифры и картинки обновились. График курса — «Показать подробности» |
| 7 | Все пациенты | Одна фраза о группе и список с подписями колонок («начало курса → сейчас», «за курс»): кто прибавляет, у кого откат к прошлому сеансу (Томирис после перерыва), у кого плато — по правилам наблюдений. Графики — «Показать подробности» |

После показа — **«Сбросить демо»** в тёмной полосе «Демо» сверху: мгновенно, из сохранённого снимка.

Сценарии симуляции (экран «Новый тест», источник «Симулятор»): обычный сеанс, нестабильная связь,
садится батарея, утомление пациента, движение при калибровке. Во время теста сбои можно вызвать
вручную — кнопка «Сбои».

**Цифры страницы — из системы.** Сцены 2, 4, 5, 6 и финал читают первого ребёнка демо (Алихан,
внутренний ключ P01) из хранилища (`story.ts`) теми же функциями, что карточка пациента. Рисунки
«Специалистам» считает модель движения демо (`studyData.ts`, тест `studyData.test.ts`). Числа
«Проверки» (41°, 1,6°, 60 / 55 / 5) сверяет с файлами прогона тест `proofData.node.test.ts`.

**Фото — концепт-изображения**, не снимки настоящего устройства или пациента: так и подписано на
экране. Откуда они и что можно о них говорить — `src/assets/README.md`.

Движение — как на страницах-презентациях Apple (с 18 октября; `docs/DESIGN_SYSTEM.md`, раздел 7):
текст появляется подъёмом на 30 px, когда доходит до 82 % экрана; фото датчика, модель датчика,
планшет, рука на листе отчёта и рисунки движений идут вместе с прокруткой.
Без библиотек: `IntersectionObserver`, один обработчик прокрутки на кадр и `MutationObserver`
для блоков, которые появляются после загрузки данных (`motion.ts`). Живые рисунки считают кадры,
только пока видны. «Уменьшить движение» в системе — всё сразу на месте: шкала на фото нарисована,
фото датчика во весь экран, модель меняется шагами, рисунки движений целиком, тур не идёт сам.

## Что умеет MVP

**Простой вид и подробности.** Все экраны врача открываются в простом виде — главное крупно, словами
и картинками:

| Экран | Простой вид | За «Показать подробности» |
|---|---|---|
| Главная | четыре цифры дня, расписание на сегодня (у следующего пациента — главная кнопка «Начать тест»), «требуют внимания», «как идут дела» — строка на пациента с подписями колонок; в демо — «Впервые здесь?» | таблица динамики со спарклайнами, комплект, лента действий |
| Новый тест | пациент, протокол, план со значками движений и кнопка «Надеть датчики» | источник данных, сценарии симуляции, число повторов, автопереход |
| Тест вживую | одна карточка: что делать, повторы, угломер с прошлым сеансом и целью, фигурка; кнопки — пауза, следующий шаг, экран для пациента, завершить | живые кривые, каждый повтор с плавностью, связь и заряд, список шагов, перекалибровка, сбои |
| Карточка пациента | фраза о курсе, три картинки с цифрами (подъём руки, правая и левая, помощь корпусом), наблюдения | плитки, график курса, цели, последний сеанс; правка, выгрузка и удаление пациента |
| Отчёт о сеансе | фраза и строка на движение со схемой обеих рук, полнота записи | таблица со SPARC, графики, повторы, заключение, качество |
| Аналитика | фраза о группе и тот же список «как идут дела» | фильтры и все графики группы |

**Картинки к цифрам** (`src/charts/MoveFigures.tsx`). «145°» без картинки ничего не говорит человеку,
который видит NeuroMove впервые. Поэтому у каждой главной цифры простого вида — схема тела по
настоящим числам: `RaiseProgress` — шкала 0°…180° вокруг плеча (0° — рука вдоль тела, 180° — прямо
вверх), серый сектор — начало курса, оранжевый — прибавка, ромб — цель врача; `ArmsCompare` — обе
руки в одном движении (подъём вперёд и локоть — сбоку, отведение — спереди, поворот — дуга «ладонь
вниз … ладонь вверх»); `TrunkLean` — наклон корпуса от прямой спины. Те же схемы — значками в плане
сеанса и в «Отчёте для семьи». Изменение — одной меткой: стрелка — куда сдвинулось, цвет — к лучшему
ли (для корпуса лучше меньше), текст — «было …».

**Гид** (`src/features/demo/`) — карточка над экраном, в потоке страницы, а не окно поверх: не
закрывает то, о чём рассказывает. На телефоне — карточка над нижней навигацией, лента шагов — без
подписей. Экран отмечает свой главный блок (`useGuideSpot` в `spot.ts`), гид по шагу решает, чей
он сейчас, и блок обводится рамкой цвета гида.

Слова — по порогам «Отчёта для семьи» и правилам наблюдений (откат 10°, плато 4 сеанса в пределах 6°);
ничего не удалено. Режим один на все экраны и запоминается в настройках, «Попробовать демо» всегда
начинает с простого вида. Логика «главного» одна для приложения и стартовой страницы — `src/session/story.ts`.

**Для специалиста**
- Обзор дня: расписание, наблюдения, требующие внимания, динамика пациентов, устройство.
- Пациенты — по имени, без фамилии, ИИН и фото (правило из `софт.md`, раздел 4; до 17 октября 2026 — коды
  вроде P07, старые архивы с кодами читаются). Форма ДЦП, сторона, GMFCS, MACS.
- Карточка пациента: ключевые метрики с изменением к началу курса, график динамики по любой
  метрике и движению, цели терапии с прогрессом, заметки, история сеансов, наблюдения.
- Новый сеанс: протокол (стандартная оценка, быстрая проверка, выносливость, свой набор,
  проверка одним датчиком), повторы 3 или 5, источник данных, сценарий симуляции.
- **Проверка одним датчиком** (22 октября): где он надет — плечо или предплечье — и какой рукой.
  На плече — подъём руки вперёд и в сторону, на предплечье — поворот. Это проверка железа и одного
  угла против гониометра, а не оценка пациента: для неё нужны три датчика сразу. Локтя в этом режиме
  нет — одним датчиком он считается только при неподвижном плече, а при ДЦП ошибка 5–19° на модели
  пациента (`log/2026-10-22-один-датчик.md`). Единственный датчик потока приложение называет
  выбранным местом (`devices/SinglePlacementDevice.ts`); подъём и поворот совпадают с полным
  комплектом до 0,5° (`session/singleSensor.test.ts`).
- Живой тест: подключение → калибровка → шаги протокола. Пауза, следующий шаг, перекалибровка,
  досрочное завершение, экран для пациента, горячие клавиши (пробел, N, P).
- Отчёт о сеансе: таблица «движение × сторона», пары полос Л/П, сравнение с прошлым сеансом,
  запись угла каждого шага с пиками повторов, события сеанса, качество данных, выгрузка сырых
  данных в CSV (imu-csv v1).
- Печать и PDF (A4, водяной знак «ДЕМО» для демо-данных), отчёт для семьи простыми словами.
- Аналитика группы: изменение объёма, объём по неделям курса, симметрия, плавность, наклон
  туловища, нагрузка по неделям, полнота данных. У каждого графика есть таблица.
- Три языка: русский, казахский, английский.

**Для проверки точности — стенд и добровольцы (SMART v2, пункт M)**
- «Датчики» → «Проверка точности»: запись станка или добровольца с отметками эталона
  `# mark seq=… ref=…` → угол прибора у каждой отметки теми же формулами, что живой тест
  (`core/validation.ts`) → таблица «эталон — прибор — ошибка», средняя и наибольшая ошибка,
  смещение и пределы согласия Бланда — Альтмана, итог против порога 5°, записанного до замера.
- «Запись с датчиков» там же: начать запись, 3 с калибровки, на каждом угле — вписать угол
  и «Отметка», «Остановить». Файл imu-csv v1 с паспортом (`kind=bench`, движение, сторона)
  и отметками сохраняется на диск и сразу загружается в проверку. Заменяет `record.py` из плана.
- Запись симулятора подписана «проверены формулы, а не прибор». На записи станка из симулятора
  (`simulation/bench.ts`, 3 разных «надевания») средняя ошибка — 0.18–0.97°, наибольшая — 2.2°.
  Кнопка «Пример: станок на симуляторе» показывает метод за один клик — для показа без железа.

**Надёжность**
- Обрыв связи во время теста → автоматическая пауза, переподключение (5 попыток),
  продолжение по кнопке; прерванный повтор не засчитывается.
- Страница закрылась или перезагрузилась посреди теста → при следующем открытии:
  продолжить (переподключить датчики и повторить калибровку), сохранить собранное или удалить.
- Калибровка повторяется, если пациент двигался.
- Нет IndexedDB (приватное окно) → работа в памяти и честное предупреждение.
- Нет интернета → работает, данные остаются на компьютере.
- Архив пространства (JSON) и выгрузка метрик (CSV) — в «Настройках».

**Наблюдения после сеанса** — правила на измерениях, не диагноз и не рекомендация:
объём упал на 10° и больше; наклон туловища 12° и больше и вырос; полнота данных ниже 95%;
достигнута цель; сеанс прерван; нарушены условия замера; плато (4 сеанса в пределах 6°
и тренд меньше 1° за сеанс).

**Черновик заключения** собирается по правилам из измерений — без ИИ: данные детей не уходят
во внешние сервисы, а каждая фраза проверяется по таблице отчёта. Специалист правит и сохраняет.

## Архитектура

```
Датчики / симулятор / файл ─► NeuroMoveDevice ─► SessionEngine ─► Session ─► хранилище
   (сырые int16 по контракту)   (единый интерфейс)  (углы, повторы,   (запись)   (IndexedDB)
                                                      метрики)
                                                         │
                                          экраны читают снимки движка и данные хранилища
```

Три правила, которые держат всё вместе:

1. **Интерфейс не знает, откуда данные.** Симулятор, USB, Bluetooth и файл записи реализуют
   один интерфейс `NeuroMoveDevice` (`src/devices/types.ts`) и отдают одно и то же —
   **сырые** числа датчиков, как в контракте с железом (`софт.md`, раздел 1).
2. **Углы и метрики считает приложение, а не устройство** — в `src/core` (перенос `imu.py`,
   `angles.py`, `reps.py`, `metrics.py` из плана лаборатории). Экраны сами ничего не считают.
3. **Демо и клиника не смешиваются.** Два рабочих пространства; симулятор доступен только
   в демо — смоделированные данные не попадают в историю настоящих пациентов.

### Симулятор — полноценная имитация, а не картинка

- `simulation/VirtualPatient.ts` — «ребёнок»: выполняет указания специалиста (движение, сторона,
  отдых, «замри»), с индивидуальным ограничением объёма, прерывистостью движения (подшаги
  минимального рывка), компенсацией туловищем, утомлением, плавными переходами позы.
- `simulation/kinematics.ts` — модель тела: углы в суставах → положение и поворот пяти датчиков.
- `simulation/imuModel.ts` — что видят акселерометр и гироскоп MPU-6050: гравитация, линейное
  ускорение, угловая скорость, шум, смещение гироскопа, перекос крепления, округление до int16,
  упор в диапазон.
- `devices/SimulatorDevice.ts` — устройство: поиск, датчики на связь по одному, поток 100 Гц,
  заряд, качество связи, сбои (обрыв, потери пакетов, разряд, утомление).

**Все цифры демо-истории посчитаны теми же алгоритмами, что и живой тест.** Для каждого прошлого
сеанса виртуальный пациент «выполняет» тест, модель выдаёт сырые числа, `SessionEngine` считает
углы и метрики. Вписано руками только одно — насколько ограничены движения ребёнка в каждый день
курса (`data/seed/demo.ts`). Генерация — ~1.6 с при первом запуске, дальше — снимок.

### Как подключить настоящее железо

Контракт уже реализован — остаётся проверить на стенде:

| Способ из `железо.md` | Класс | Что готово | Что сделать |
|---|---|---|---|
| А — провода, ESP32 → USB | `devices/SerialDevice.ts` | Web Serial 460800 (с 12 октября; 921 600 на маке с CH340C не работает), паспорт и строки imu-csv v1, учёт потерь по `seq`, переподключение | Проверить на стенде Санжара |
| Б — Bluetooth-блоки | `devices/BleDevice.ts` | Web Bluetooth, пакет 18 байт, заряд (0x180F), команда старт/стоп, переподключение | Вписать UUID из прошивки в `BLE_UUIDS`; синхронизация часов блоков (удар о стол) |
| В — блоки → хаб → USB | `SerialDevice` | тот же формат, что у способа А | — |
| Запись из лаборатории | `devices/ReplayDevice.ts` | проигрывание CSV как вживую | — |

Новый источник — ещё один класс с интерфейсом `NeuroMoveDevice`. Экраны, движок и отчёты
менять не нужно.

### Хранение

IndexedDB (`data/db.ts`): пациенты, сеансы, заметки, наблюдения, служебные записи и сырые отсчёты
кусками. Замена на сервер позже — новая реализация интерфейса `DataStorage`, остальной код
не меняется. Облако (Supabase) — только когда центр и куратор скажут, где можно хранить данные
детей (`софт.md`, раздел 4).

## Алгоритмы и проверка точности

Точность и надёжность проверены 2 октября 2026 на независимом эталоне (своя кинематика и модель MPU-6050 по даташиту): [`docs/ENGINEERING_10H/`](docs/ENGINEERING_10H/) — эксперименты, находки, оси координат, приёмка железа.

| Что | Как | Проверено |
|---|---|---|
| «Верх» датчика | комплементарный фильтр: 98% — гироскоп, 2% — акселерометр (`core/orientation.ts`) | тесты |
| Подъём сегмента | **угол между «верхом» сейчас и в позе калибровки** (`core/pipeline.ts`) | средняя ошибка 0.1–1.5°, пик ±3° |
| Сгибание локтя | поворот в шарнире локтя со знаком: ось — Z датчика плеча (`elbowFlexion`); контроль «плечо прижато» | независимый эталон: плечо до 20° назад, вперёд, в сторону — худшая ошибка объёма 1,6° (было до 41°) |
| Пропавший датчик | показание старше 0,25 с не используется; пометка шага, событие с местом датчика (`missingSensors`) | тест на независимом эталоне |
| Поза калибровки | наклон каждого датчика от вертикали хранится с сеансом; с 15° — событие и строка в отчёте | контрактура 25° видна, перекос ремешка 8° тревоги не даёт |
| Поворот предплечья | поворот вокруг оси кости, нейтраль ловится на установке | ошибка < 1.5° |
| Повторы | гистерезис, два порога (`core/reps.ts`) | 3 из 3 |
| Плавность | SPARC, Balasubramanian и др., 2015 (`core/sparc.ts`) | минимальный рывок = −1.40 |
| Метрики | медиана повторов, симметрия, CV, наклон туловища (`core/metrics.ts`) | тесты |
| Проверка точности | медиана угла ±0.5 с у отметки эталона; MAE, максимум, Бланд — Альтман (`core/validation.ts`) | запись станка из симулятора: MAE 0.18–0.97° |
| Поправки акселерометра | ноль и масштаб осей из калибровки в 6 положениях (прошивка, `cal`); паспорт `# cal_<место>=…` → `DeviceInfo.accCal` → поток, поза калибровки, проверка точности, выгрузка (`core/imu.ts`) | заводской ноль 0,05 g: без поправок до 6,5°, с поправками 0,24–0,36° |
| Поток с USB | куски порта → строки с пределом 4096 знаков (`LineSplitter`); seq только растёт — перезагрузка платы и 16-битный seq не поворачивают время вспять, одна испорченная цифра не даёт ложного разрыва (`SeqUnwrapper`, `devices/contract.ts`) | тесты со случайными границами кусков; 2 000 случайных последовательностей номеров; образцы протокола от прошивки |

«Проверено» — на данных симулятора с шумом, смещением гироскопа и перекосом крепления 2–5°,
5 разных «надеваний» × 4 движения × 2 стороны. Критерий из `софт.md` — ошибка < 3° — выполнен.
**На людях будет хуже** — поэтому критерий для стенда отдельный: ≤ 5° против гониометра.

⚠️ **Отличие от `софт.md`.** Там подъём = arccos(−g_x): считается, что ось X датчика идёт точно
вдоль кости. При перекосе ремешка на 2–5° ошибка на высоких углах доходила до 10° — поправка
калибровкой верна только около нуля. Здесь подъём — угол между направлением «вверх» сейчас
и в позе калибровки (руки висят вдоль тела, значит, направление кости в осях датчика известно
точно). Формула точная при любом перекосе. **Эту же формулу стоит взять в лабораторию на Python**,
иначе golden-тесты Python и приложения не совпадут.

Тесты: `npm test` — 112 юнит-тестов: углы, повторы, SPARC, контракт imu-csv v1 и пакет BLE,
происхождение записи (демо или нет), числа вне int16, сеанс целиком (калибровка, пауза, обрыв связи,
досрочное завершение, продолжение после перезагрузки), деления осей, «главное словами» на демо-данных,
разбор и проверка архива, CSV без формул, имена файлов выгрузки, запрет смоделированных сеансов
в клинике, поток с USB (куски, мусор, перезагрузка платы, 16-битный seq), проверка точности
по отметкам эталона, маршруты. `npm run e2e` — сквозные тесты в Chrome: путь демо на компьютере и телефоне,
обрыв связи, перезагрузка посреди теста, отказ демо-записи в клинике (и сконструированной, и настоящей
выгрузки), CSP, демо одним файлом с диска, ширины 320–1440 px на трёх языках, axe WCAG 2.1 AA,
клавиатура, проверка точности и запись с датчиков с отметками. Итоги — `docs/TEST_REPORT.md`.

## Стек и почему

| Что | Чем | Почему |
|---|---|---|
| Сборка | Vite 7, TypeScript 6 (strict) | быстро; типы ловят ошибки в разборе байтов до запуска |
| Интерфейс | React 19 + Zustand | в плане было «без фреймворка — экранов шесть»; экранов стало больше десяти с общим состоянием, модальными окнами и живыми данными. Ядро (`core/`, `devices/`, `session/`, `simulation/`) от React не зависит |
| Графики | свои SVG и `<canvas>` | в плане был Chart.js; свои графики — точнее по дизайну, печатаются чётко, без лишней зависимости. Живая кривая — canvas, 60 кадров/с без перерисовки React |
| Хранение | IndexedDB через `idb` | как в плане |
| PDF | печать браузера, `@media print` | как в плане — библиотека не нужна |
| Тесты | Vitest; Playwright + axe-core для сквозных | Vitest — как в плане; Playwright гоняет собранный сайт в установленном Chrome, ничего не скачивая |
| Иконки, шрифты | lucide-react, Inter и JetBrains Mono (внутри сборки) | шрифты вшиты: в клинике может не быть интернета |

## Известные ограничения

- **Железа ещё нет.** USB и Bluetooth реализованы по контракту, но не проверены на устройстве.
  UUID Bluetooth и синхронизация часов блоков — после прошивки.
- **Точность проверена только на симуляторе.** На людях — отдельная проверка против гониометра
  (`README.md` проекта, раздел 8).
- **Казахский текст** написан без проверки носителем языка: медицинские термины стоит вычитать
  (Малика, врач центра).
- **Нормативов нет намеренно.** Отчёт сравнивает ребёнка с его другой стороной и с его прошлыми
  сеансами, а не с «нормой»: без проверенного источника норм показывать их нельзя.
- **Наблюдения — правила, а не клиника.** Пороги (10°, 12°, 95%, плато 6°) — условия внимания
  для специалиста, их нужно согласовать с врачом.
- **Данные только на одном компьютере.** Синхронизации нет; архив JSON — вручную.
- **Демо генерируется заново**, когда меняется версия демо-данных (`DEMO_SEED_VERSION`), —
  сеансы, записанные в демо, при этом пропадают. Пространство клиники не затрагивается.
- **Сырые данные** сохраняются для живых сеансов; для сгенерированной истории — только метрики
  и прореженная запись угла.
- **Нет входа по паролю и шифрования на диске.** «Пространство клиники» — локальный профиль
  специалиста на этом компьютере; это сказано в онбординге и «Настройках». Учётные записи и права
  появятся вместе с сервером. До тех пор — своя учётная запись ОС и шифрование диска.
- **На GitHub Pages все проекты аккаунта делят один origin** (`<имя>.github.io`), а с ним IndexedDB.
  Для данных детей — только отдельный origin (`docs/SECURITY_PRIVACY.md`, R3).
