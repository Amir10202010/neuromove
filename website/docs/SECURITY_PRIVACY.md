# NeuroMove — безопасность и приватность

Состояние на 1 октября 2026. Раздел 2 — что **сделано в коде** и чем проверено. Раздел 3 — что
**не закрыто**. Раздел 5 — вопросы, которые решает не программист.

Данные, о которых речь: движения детей с ДЦП — данные о здоровье несовершеннолетних. Даже без имён,

## 1. Модель угроз — коротко

| Кто или что | Что может случиться | Насколько вероятно сейчас |
|---|---|---|
| Человек за тем же компьютером | открыть браузер и увидеть пациентов клиники | **высоко**: пароля нет |
| Чужой файл архива или записи | формула для Excel в ячейке, мусорные данные, подмена «демо» на «клинику», зависание вкладки | средне: файлы ходят по почте и флешкам |
| Код на том же origin | прочитать IndexedDB приложения | средне при хостинге на `*.github.io` (раздел 3) |
| Утечка по сети | приложение отправляет данные куда-то | низко: сетевого кода нет, CSP запрещает запросы |
| Демо принято за настоящие данные | решение по смоделированной цифре | средне на показах: закрыто пометками и запретами |
| Ошибка измерения принята за клиническую | неверный вывод о прогрессе | **высоко** до проверки на людях: закрыто оговорками, не кодом |

## 3. Что не закрыто

| # | Риск | Почему не закрыто | Что делать до настоящих данных |
|---|---|---|---|
| R1 | **Нет пароля и разграничения прав.** «Пространство клиники» — локальный профиль | сервера нет; авторизация только в браузере была бы видимостью защиты | отдельная учётная запись ОС у специалиста, шифрование диска (FileVault, BitLocker), блокировка экрана |
| R2 | **Данные на диске не зашифрованы** (IndexedDB, архив JSON) | шифрование паролем — отдельная работа с риском потерять данные при забытом пароле | ПРЕДЛОЖЕНИЕ: AES-GCM через Web Crypto, ключ из пароля (PBKDF2), шифруются записи пациентов и сеансов; до этого — шифрование диска |
| R3 | **Общий origin на GitHub Pages.** Все проекты аккаунта на `<имя>.github.io/*` делят origin, а с ним IndexedDB | особенность хостинга | клинические данные — только с отдельного origin (свой домен или отдельный аккаунт); `*.github.io` — только для демо |
| R4 | **Апостроф в CSV Excel может снять** при пересохранении (OWASP) | ограничение формата | не пересохранять выгрузку в CSV, работать в .xlsx |
| R5 | **Нет журнала доступа** | один пользователь на компьютере, сервера нет | вместе с сервером: кто открыл карточку, кто выгрузил |
| R6 | **Срок хранения не задан** | решает центр | после решения — напоминание об удалении выписанных пациентов |
| R7 | **Сырые данные устройства — не проверены на настоящем железе** | железа нет | разбор строк устойчив к мусору (тесты), но фаззинг на потоке с ESP32 — после стенда |
| R8 | **`frame-ancestors` нельзя задать через `<meta>`** — страницу можно встроить в чужой фрейм | GitHub Pages не даёт заголовков | на своём хостинге — заголовок `Content-Security-Policy: frame-ancestors 'none'` |

## 4. Права и данные детей — правила для кода (не меняются без центра)

- В приложение не попадают ФИО, ИИН, фото и видео с лицом. Таблица «код — ребёнок» живёт в центре.
- Демо всегда подписано «ДЕМО» и не попадает в историю детей.
- Приложение не ставит диагноз и не даёт рекомендаций: наблюдения — правила на измерениях,
  выводы делает врач.
- Ничего не отправляется по сети, пока центр не решил, где можно хранить данные.
