# Эксперименты: точность углов на независимом эталоне

Раздел «Критерии» записан **2 октября 2026 в 07:35, до первого прогона**. Результаты
дописываются ниже, критерии после прогона не меняются. Если критерий не выполнен — это
находка в `FINDINGS.md`, а не повод сдвинуть порог.

## Зачем независимый эталон

Прежняя проверка углов шла на симуляторе приложения (`src/simulation/`). Он написан тем же
человеком и с теми же допущениями, что и формулы: например, при сгибании локтя симулятор
отрывает плечо только **вперёд** — ровно то направление, при котором формула локтя верна.
Такая проверка не может найти ошибку в допущении, потому что повторяет его.

Эталон `src/verification/` построен заново:

| | Симулятор приложения | Эталон |
|---|---|---|
| Повороты | матрицы 3 × 3, `lib/vec3` | кватернионы, свой код |
| Оси мира | x вперёд, y влево, z вверх | X вправо, Y вперёд, Z вверх |
| Плечо | сгибание, затем отведение | плоскость подъёма + подъём + поворот вокруг кости (как в рекомендациях ISB) |
| Локоть | поворот вокруг оси y мира в осях плеча | шарнир с осью, закреплённой в плече, плюс угол вальгуса |
| Ускорение | вторая разность положений по отсчётам 100 Гц | центральная разность 4-го порядка по непрерывному времени |
| Гироскоп | разность матриц соседних отсчётов | производная кватерниона, 4-й порядок |
| Датчик | шум и смещение, без фильтра | модель MPU-6050 по даташиту: внутренние 1 кГц, фильтр DLPF ≈ 44 Гц с задержкой ~4,9 мс, ноль и масштаб, перекрёстная чувствительность, шум, округление, упор |
| Случайные числа | mulberry32 (`lib/random`) | xoshiro128** — свой код |

Из кода приложения эталон берёт только то, что проверяется: `MotionPipeline`, `Calibrator`,
`exerciseSample` (как в `core/validation.ts`) и `SessionEngine` для объёма движения по повторам.

## Метрики

По каждому сценарию: средняя ошибка со знаком (прибор − эталон), MAE, RMSE, P95 модуля,
максимум модуля, доля отсчётов, где прибор дал угол (покрытие). Окно расчёта — после
окончания калибровки + 0,5 с. Для объёма движения — ошибка ROM по каждому повтору,
посчитанному `SessionEngine`, против максимума угла эталона в том же повторе.

| C4-flick «до» | упор датчика считался, но флаг шага `saturation` нигде не ставился | исправлено (P1-5), в финальном прогоне проходит |
| C13x-hyperextension | переразгибание локтя при висящем плече по гравитации неотличимо от сгибания: +10° вместо −10° (F3). У старой формулы то же самое | ограничение метода; объём (пик) не страдает |
| C13x-carrying-pronation | вальгус 10° и пронация 60° во время сгибания: объём занижен на 8–10° (F4). У старой формулы то же самое | ограничение метода «угол от позы калибровки»; проверить на станке с поворотом предплечья |
